# Уютный Квадрат — сайт посуточной аренды квартир

Сайт посуточной аренды с онлайн-бронированием и **панелью менеджера**.
Фронтенд — чистый **HTML / CSS / JS** (без сборки и фреймворков).
Бэкенд — **Node.js + Express**, база данных — **SQLite**. Развёртывание — **Railway**.

Редизайн по мотивам сайта уютныйквадрат.рф: свой дизайн (тёплый уютный минимализм),
своя вёрстка, своя логика и своя база данных.

## Что умеет

- **Публичный сайт** (`/`): каталог квартир с фильтрами, карточки с деталями,
  форма бронирования с расчётом стоимости, отзывы, FAQ, контакты.
- **Заявки идут в общую базу** через API. Уведомление о новой брони приходит
  менеджеру в **Telegram** (токен спрятан на сервере, в браузер не попадает).
- **Панель менеджера** (`/manager`): вход по логину/паролю, список всех броней из
  общей базы, сводка, фильтры по статусу, поиск, смена статуса, ручное добавление
  брони, удаление, экспорт в CSV. Данные видны всем менеджерам с любого устройства.

## Структура

```
server.js            — сервер Express: API + раздача статики
lib/
  db.js              — SQLite: схема и запросы
  auth.js            — авторизация менеджера (подписанная httpOnly-cookie)
  notify.js          — уведомления о бронях в Telegram
public/              — фронтенд (раздаётся сервером)
  index.html         — публичный сайт
  manager.html       — панель менеджера
  apartments.json    — каталог квартир (единый источник данных)
  css/ js/ assets/   — стили, скрипты, картинки
package.json         — зависимости и скрипты (npm start)
.env.example         — список переменных окружения
```

## Локальный запуск

```bash
npm install
cp .env.example .env      # при желании поправьте значения
npm start                 # или npm run dev — с авто-перезапуском
```

Откройте <http://localhost:3000> — сайт, <http://localhost:3000/manager> — панель.
Логин/пароль менеджера по умолчанию: `manager` / `admin123` (задайте свои в `.env`!).
База данных создаётся автоматически в `./data/bookings.db`.

## Переменные окружения

| Переменная            | Назначение                                                        |
|-----------------------|-------------------------------------------------------------------|
| `PORT`                | Порт сервера (Railway задаёт сам; локально 3000)                  |
| `ADMIN_USERNAME`      | Логин менеджера (по умолчанию `manager`)                          |
| `ADMIN_PASSWORD`      | **Пароль менеджера — обязательно задайте свой**                   |
| `SESSION_SECRET`      | Секрет для подписи cookie (длинная случайная строка)              |
| `COOKIE_SECURE`       | `true`, если сайт по HTTPS (на Railway — `true`)                  |
| `DATABASE_PATH`       | Путь к файлу БД (на Railway — внутри Volume, см. ниже)            |
| `TELEGRAM_BOT_TOKEN`  | Токен бота от @BotFather (необязательно)                          |
| `TELEGRAM_CHAT_ID`    | Chat_id менеджера/группы (необязательно)                          |
| `BRAND_NAME`          | Название бренда в уведомлениях                                    |

Секрет для cookie удобно сгенерировать так:
```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

## Деплой на Railway

1. Создайте проект на <https://railway.app> → **Deploy from GitHub repo** и выберите
   этот репозиторий. Railway сам определит Node, поставит зависимости и запустит
   `npm start`.
2. В разделе **Variables** задайте переменные: как минимум `ADMIN_PASSWORD`,
   `SESSION_SECRET`, `COOKIE_SECURE=true`. Для Telegram — `TELEGRAM_BOT_TOKEN` и
   `TELEGRAM_CHAT_ID`. `PORT` Railway задаёт автоматически.
3. **Постоянное хранилище (важно!).** Файл SQLite нужно хранить на диске, который
   переживает передеплой. Добавьте **Volume** (Railway → сервис → *Volumes*),
   примонтируйте его, например, в `/data`, и задайте переменную:
   ```
   DATABASE_PATH=/data/bookings.db
   ```
   Без Volume база будет очищаться при каждом передеплое.
4. Нажмите **Deploy**. Railway выдаст публичный URL (по HTTPS). Панель менеджера —
   по адресу `<ваш-домен>/manager`.

### Настройка Telegram-уведомлений

1. В Telegram: **@BotFather** → `/newbot` → получите **токен**.
2. Напишите боту любое сообщение (или добавьте его в группу менеджеров).
3. Узнайте **chat_id**: бот **@getmyid_bot**, либо откройте
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id":...}`.
4. Задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в Variables на Railway.

Уведомления присылает **сервер**, поэтому токен не виден в браузере.

## API (кратко)

| Метод и путь                     | Доступ    | Назначение                         |
|----------------------------------|-----------|------------------------------------|
| `POST /api/bookings`             | публичный | создать бронь (заявка с сайта)     |
| `POST /api/login`                | публичный | вход менеджера                     |
| `POST /api/logout`               | менеджер  | выход                              |
| `GET  /api/me`                   | —         | проверка сессии                    |
| `GET  /api/bookings`             | менеджер  | список всех броней                 |
| `PATCH /api/bookings/:id`        | менеджер  | сменить статус                     |
| `DELETE /api/bookings/:id`       | менеджер  | удалить бронь                      |
| `DELETE /api/bookings`           | менеджер  | очистить все брони                 |
| `POST /api/bookings/seed-demo`   | менеджер  | заполнить демо-данными             |

Стоимость брони считается **на сервере** по цене из `apartments.json` — клиент не
может её подделать. Пользовательский ввод экранируется, статусы валидируются.

## Настройка контента

- **Квартиры** — `public/apartments.json` (цена, площадь, фото, описание).
- **Контакты на сайте** — `public/js/config.js` (телефон, адрес, соцсети).
- **Фотографии** — замените SVG-заглушки в `public/assets/img/` на реальные фото
  и обновите пути `image` в `apartments.json`.
